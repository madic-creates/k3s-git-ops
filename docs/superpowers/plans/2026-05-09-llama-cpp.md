# llama.cpp on k3s with NVIDIA GPU — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy two new ArgoCD applications to this k3s cluster — `nvidia-device-plugin` (advertises `nvidia.com/gpu` as a schedulable resource on node04) and `llama-cpp` (an OpenAI-compatible inference endpoint at `https://llama.internal.neese-web.de` running Qwen2.5-Coder-7B-Instruct Q4_K_M with 32 k context, agent-tuned).

**Architecture:** Two GitOps apps, deployed in dependency order via ArgoCD sync waves (24 → 65). Phase 1 must be live and advertising `nvidia.com/gpu` on node04 before Phase 2 begins. The model file is staged manually on node04 under `/zfs/llama-cpp/models/` and verified at pod startup by an init container (file existence + GGUF magic bytes + pinned SHA256). All secrets are SOPS-encrypted; ksops decrypts them at `kustomize build` time. Auth is a single shared bearer token enforced by llama.cpp's `--api-key-file`. Ingress is plain `networking.k8s.io/v1 Ingress` annotated for Traefik on the internal entrypoint pair.

**Tech Stack:** k3s v1.31 · ArgoCD · Kustomize + Helm · ksops + SOPS + age · Cilium NetworkPolicies · Traefik ingress · cert-manager (existing wildcard cert) · NVIDIA k8s-device-plugin (Helm) · llama.cpp server (CUDA build) · Renovate.

**Approved spec:** `docs/superpowers/specs/2026-05-09-llama-cpp-design.md`. If anything in this plan disagrees with the spec, the spec wins — stop and fix the plan first.

## Conventions for this plan

- The cluster is the source of truth for whether something works. After every push, watch `kubectl get application -n argocd <app>` until `SYNC=Synced HEALTH=Healthy`.
- "Test" in this plan = (a) `kustomize build` succeeds without error, (b) `scripts/kubeconform-validate.sh` passes, (c) `pre-commit run --all-files` is green. After deploy, also (d) `kubectl` queries return the expected state and (e) HTTP smoke tests against the endpoint succeed.
- All commits go on `main`. Push only after the full pre-commit suite is green.
- **Never** `kubectl edit` / `kubectl apply` an ArgoCD-managed object. Edit YAML, commit, push, wait for sync.
- All code comments inside YAML/scripts must be in English (see `CLAUDE.md`).
- The encrypted-file workflow is documented in `CLAUDE.md` ("Editing SOPS files from Claude Code"). Use Workflow B (decrypt to `/tmp`, edit, re-encrypt) for the multi-line files in this plan.

`apps/nvidia-device-plugin/k8s.np.nvidia-device-plugin.yaml`:

```yaml
---
# NVIDIA Device Plugin Network Policy
# The device plugin DaemonSet runs on nodes with NVIDIA GPUs and registers
# GPU resources with the kubelet. It needs:
# 1. To accept gRPC from the kubelet (host) on the device-plugin socket
# 2. DNS resolution
# 3. Outbound to host (kubelet) and the kube-apiserver
apiVersion: cilium.io/v2
kind: CiliumNetworkPolicy
metadata:
  name: nvidia-device-plugin
  namespace: nvidia-device-plugin
  annotations:
    argocd.argoproj.io/sync-wave: "24"
spec:
  endpointSelector:
    matchLabels:
      app.kubernetes.io/name: nvidia-device-plugin
  ingress:
    # Kubelet -> device plugin (registration + AllocateResponse)
    - fromEntities:
        - host
  egress:
    # DNS via CoreDNS
    - toEndpoints:
        - matchLabels:
            k8s:io.cilium.k8s.namespace.labels.kubernetes.io/metadata.name: kube-system
            k8s:io.kubernetes.pod.namespace: kube-system
            k8s:k8s-app: kube-dns
      toPorts:
        - ports:
            - port: "53"
              protocol: UDP
            - port: "53"
              protocol: TCP
    # Device plugin -> kubelet (host) over the device-plugin socket
    - toEntities:
        - host
    # Device plugin -> kube-apiserver for node status
    - toEntities:
        - kube-apiserver
```

> **Note on the `endpointSelector` label.** The NVIDIA chart sets the standard `app.kubernetes.io/name=nvidia-device-plugin` label on the DaemonSet pod template. If Task 1.6 reveals different labels in the rendered manifest, update this selector accordingly before Task 1.7.

- [ ] **Step 1: Write the Deployment + Service**

`apps/llama-cpp/k8s.deployment.yaml`:

```yaml
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: llama-cpp
  namespace: llama-cpp
  labels:
    app: llama-cpp
spec:
  replicas: 1
  revisionHistoryLimit: 2
  strategy:
    # Single-tenant GPU; rolling would deadlock on nvidia.com/gpu.
    type: Recreate
  selector:
    matchLabels:
      app: llama-cpp
  template:
    metadata:
      labels:
        app: llama-cpp
    spec:
      runtimeClassName: nvidia
      nodeSelector:
        node-role/workload: zfs
      initContainers:
        # Fail fast with a clear error if the operator forgot to stage the
        # GGUF on node04, or if the file got truncated. Cheaper than a
        # CrashLoop on the main container, which buries the cause in
        # llama.cpp logs.
        - name: verify-model
          image: alpine:3.20
          command:
            - sh
            - -c
            - |
              set -eu
```
